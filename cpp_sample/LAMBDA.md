# Modern C++ ラムダ式 完全理解ガイド (Modern C++ Lambdas Deep Dive)

C++11 で導入され、C++14 / C++17 / C++20 / C++23 と規格が進むごとに劇的な進化を遂げてきた **C++ の最重要機能「ラムダ式（Lambda Expressions）」** の完全解説書です。

Java や C# のラムダ式とは異なり、C++ のラムダ式は **「ゼロオーバーヘッド原則（Zero-overhead principle）」** に基づいて設計されており、コンパイラが裏で生成するマシンコードは通常のインライン関数と全く同じ速度で動作します。

## 1. ラムダ式の誕生背景と本質（C++03 ファンクタの苦痛）

### 1-1. C++03 以前：関数オブジェクト（ファンクタ）の儀式
C++11 より前、`std::sort` や `std::for_each` などの STL アルゴリズムに「カスタム処理」を渡すには、**`operator()` をオーバーロードした構造体（関数オブジェクト / ファンクタ）** をわざわざクラス外に手書きする必要がありました。

```cpp
// ❌ C++03 以前: ほんの少し条件を変えたいだけなのに構造体を定義しなければならない
struct IsGreaterThan {
    int threshold;
    IsGreaterThan(int t) : threshold(t) {}
    bool operator()(int x) const {
        return x > threshold;
    }
};

// 呼び出し側
std::vector<int> v = { 10, 25, 40, 5 };
std::find_if(v.begin(), v.end(), IsGreaterThan(20));
```

- **問題点**: ロジックが呼び出し箇所から遠く離れ、コードの見通しが極めて悪くなる。

### 1-2. C++11 以降：インラインでの無名ファンクタ生成
ラムダ式を使うことで、**その場で無名の関数オブジェクトを生成**できるようになりました。

```cpp
// ⭕ Modern C++: 呼び出し箇所に直接書ける
int threshold = 20;
std::find_if(v.begin(), v.end(), [threshold](int x) { return x > threshold; });
```

## 2. 完全構文解剖（全パーツの意味と省略規則）

C++20 におけるラムダ式のフル構文は以下のようになります：

```cpp
[キャプチャ] <テンプレート引数> (パラメータ引数) mutable noexcept 属性 -> 戻り値の型 requires 制約 {
    処理本文
}
```

### 各構成要素と省略ルール
| 構成要素 | 記法例 | 省略可否 | 説明 |
| :--- | :--- | :--- | :--- |
| **`[キャプチャ]`** | `[]`, `[=]`, `[&]`, `[x]` | **省略不可** | 外部のローカル変数をどう取り込むかを指定 |
| **`<テンプレート>`** | `<typename T>` (C++20) | 省略可 | 汎用ジェネリックな型パラメータを指定 |
| **`(引数リスト)`** | `(int a, int b)` | **省略可** | 引数が不要な場合、`()` 自体を丸ごと省略可能 (C++11〜) |
| **`mutable`** | `mutable` | 省略可 | コピーキャプチャした変数の変更を許可する |
| **`noexcept`** | `noexcept` | 省略可 | 例外を投げないことをコンパイラに保証する |
| **`-> 戻り値型`** | `-> double` | 省略可 | コンパイラが `return` 文から自動推論できる場合は省略推奨 |
| **`requires`** | `requires std::integral<T>` | 省略可 | C++20 Concepts によるテンプレート制約 |
| **`{ 本文 }`** | `{ return a + b; }` | **省略不可** | 実行するステートメント |

#### 最も短いラムダ式
```cpp
[]{} // 引数なし、戻り値 void、何もしない最もシンプルなラムダ式
```

## 3. キャプチャリスト (`Capture`) 完全攻略 ★最重要★

ラムダ式が外部のローカル変数にどうアクセスするかを制御します。Java と異なり、**値コピー、参照、ムーブ（所有権移動）** を自由に選択できます。

```
                       ┌─────────────────────────┐
                       │  キャプチャ指定子の分類   │
                       └────────────┬────────────┘
        ┌───────────────────────────┴───────────────────────────┐
        ▼                                                       ▼
  デフォルトキャプチャ                                     個別指定キャプチャ
  [=] : 全て値コピー                                      [x]   : x を値コピー
  [&] : 全て参照                                         [&y]  : y を参照
                                                         [this]: 現在のオブジェクトポインタ
                                                         [p = std::move(ptr)] : C++14 ムーブ
```

### 3-1. `[]` (キャプチャなし)
外部の変数にアクセスしません。
> **💡 特権**: キャプチャなしラムダは、**通常の C 言語関数ポインタ（`void(*)()`）に暗黙変換可能**です！

```cpp
void (*c_func_ptr)(int) = [](int x) { std::cout << x << "\n"; };
```

### 3-2. `[=]` (デフォルト値コピー) と `mutable`
スコープ内の使用されている変数を**値コピー（スナップショット）**します。

> **⚠️ 注意: デフォルトではコピーされた変数は `const` (変更不可)**  
> Java の「実質的 final」と同様に、C++ でもコピーされた変数はデフォルトで変更できません。  
> もし変更したい場合は、**`mutable` キーワード** を付与します。

```cpp
int counter = 0;

// ❌ コンパイルエラー: counter は const としてキャプチャされる
auto bad = [counter]() { counter++; };

// ⭕ mutable を付与するとコピー変数の書き換えが可能
auto good = [counter]() mutable {
    counter++; // コピー側がインクリメントされる
    std::cout << "Inside: " << counter << "\n";
};

good(); // Inside: 1
std::cout << "Outside: " << counter << "\n"; // Outside: 0 (元の変数は不変！)
```

### 3-3. `[&]` (デフォルト参照) とダングリングの危険性
スコープ内の変数を**参照（エイリアス）**としてキャプチャします。元の変数が直接書き換わります。

```cpp
int sum = 0;
std::vector<int> nums = { 1, 2, 3 };
std::for_each(nums.begin(), nums.end(), [&sum](int n) { sum += n; });
std::cout << sum << "\n"; // 6
```

> **🚨 致命的危険（ダングリング参照）**:  
> 非同期処理（`std::async`, `std::jthread`）や戻り値としてラムダを返す場合、`[&]` を使ってはいけません。関数スタックが破棄された後にアクセスすると未定義動作（クラッシュ）になります。

### 3-4. C++14 初期化キャプチャ（Init-Capture / Generalized Capture）
C++14 から、キャプチャリスト内で新しい変数を宣言・初期化できるようになりました。
これにより、**Move-Only な型（`std::unique_ptr` 等）の所有権をラムダ内に移動**できます！

```cpp
auto ptr = std::make_unique<int>(42);

// std::move で所有権をラムダ内の uptr に移動
auto consumer = [uptr = std::move(ptr)]() {
    std::cout << "Value: " << *uptr << "\n";
};

// ここで ptr は nullptr になる
consumer();
```

### 3-5. クラスメンバのキャプチャ (`[this]` vs `[*this]`)
- `[this]`: 現在のオブジェクトへのポインタをキャプチャ。メンバ変数へのアクセスはポインタ経由。
- `[*this]` (C++17): **現在のオブジェクトを丸ごとコピーしてキャプチャ**。非同期処理で自身が破棄される可能性がある場合に安全です。

## 4. 引数の進化（C++11 から C++20 テンプレートラムダまで）

### 4-1. C++14 ジェネリックラムダ (`auto` 引数)
C++14 から引数に `auto` が使えるようになりました。これによりラムダが内部的にテンプレート関数になります。

```cpp
auto print = [](const auto& x) {
    std::cout << x << "\n";
};
print(100);       // int
print("Hello");   // const char*
print(3.14);      // double
```

### 4-2. C++20 テンプレートラムダ (`<typename T>`)
「同じ型の引数を2つ取りたい」「引数の `std::vector` の要素型 `T` を取り出したい」場合、C++14 の `auto` では型の一致を強制できませんでした。C++20 で明示的なテンプレート構文が追加されました。

```cpp
// C++14: a と b の型が異なってもコンパイルが通ってしまう
auto add14 = [](auto a, auto b) { return a + b; };

// C++20: a と b が同一の型であることを強制し、T を本文で使える
auto add20 = []<typename T>(T a, T b) {
    T temp = a + b;
    return temp;
};

// vector の要素型を直接抽出する例
auto print_vec = []<typename T>(const std::vector<T>& vec) {
    using ValueType = T;
    std::cout << "Vector size: " << vec.size() << "\n";
};
```

## 5. ラムダ式の「型」と関数の受け渡し方

C++ のラムダ式は、**コンパイラがその都度生成する「名前のない一意な型」** を持ちます。そのため、同じシグネチャのラムダでも代入できません。

```cpp
auto f1 = []() {};
auto f2 = []() {};
// decltype(f1) と decltype(f2) は全く別の型！
```

### 受け取り方の3大アプローチ比較

| 手法 | 構文例 | 速度・オーバーヘッド | 特徴 |
| :--- | :--- | :--- | :--- |
| **1. テンプレート / Concepts** (推奨) | `template <std::invocable<int> F> void run(F f)` | **最速 (ゼロオーバーヘッド)** | 完全インライン化される。STLの標準。 |
| **2. 関数ポインタ** | `void run(void (*f)(int))` | **最速** | **キャプチャなしラムダのみ**受け取り可能。C言語連携用。 |
| **3. `std::function`** | `void run(std::function<void(int)> f)` | **低速 (型消去 + ヒープ確保の可能性)** | 自由に変数を再代入・コンテナに格納できるが、仮想関数呼び出し相当のコスト。 |

## 6. 実務必須テクニック：IIFE（即時実行ラムダ）による `const` 初期化

複雑な条件分岐（`if-else` や `switch`）を経て決定される変数を、**イミュータブル（`const`）として初期化**したい場合にラムダをその場で実行する **IIFE (Immediately Invoked Function Expression)** パターンが極めて有用です。

```cpp
// ❌ 悪い例: const にできず、未初期化状態が生まれる
int port;
if (is_production) {
    port = 443;
} else if (is_staging) {
    port = 8443;
} else {
    port = 8080;
}

// ⭕ モダンC++: IIFE により一撃で const 初期化
const int port = [&]() {
    if (is_production) return 443;
    if (is_staging)    return 8443;
    return 8080;
}(); // 末尾の () で即座に実行
```

## 7. アンダー・ザ・フード：コンパイラが裏で生成するコードの正体

コンパイラは、ラムダ式を検出すると裏で**以下のような等価なクラス（クロージャ型）を合成**しています。

```cpp
// 私たちが書いたコード:
int multiplier = 5;
auto scale = [multiplier](int x) { return x * multiplier; };
int result = scale(10);
```

```cpp
// コンパイラが裏で生成している等価コード:
class __Lambda_Unique_Name_123 {
private:
    int multiplier; // キャプチャ変数がメンバ変数になる

public:
    // コンストラクタでキャプチャを初期化
    __Lambda_Unique_Name_123(int m) : multiplier(m) {}

    // operator() が呼び出される (デフォルトで const)
    int operator()(int x) const {
        return x * multiplier;
    }
};

// 実際の呼び出し:
__Lambda_Unique_Name_123 scale(multiplier);
int result = scale.operator()(10);
```

> **🚀 なぜ C++ のラムダは世界最高速なのか？**:  
> 関数ポインタ経由の間接呼び出し（間接ジャンプ）ではなく、ただの通常の構造体メンバ呼び出しであるため、**コンパイラのオプティマイザが `operator()` の中身を 100% インライン展開**します。その結果、アセンブリレベルではラムダ式のオーバーヘッドは完全に「ゼロ」になります。

## 9. 実務における重大な落とし穴とアンチパターン

### 罠1: 非同期スレッドでの参照キャプチャ（Use-After-Free）
```cpp
void start_worker() {
    int local_id = 42;
    // ❌ 危険: local_id はこの関数が終了するとスタックから消滅する
    std::jthread t([&local_id]() {
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
        std::cout << local_id << "\n"; // クラッシュまたは未定義動作！
    });
}
// 対策: 非同期処理には必ず値コピー [local_id] を使う
```

### 罠2: C++20 における `[=]` での暗黙 `this` キャプチャ非推奨
```cpp
struct Server {
    int port = 8080;
    void start() {
        // C++17以前: [=] と書くと暗黙に this がキャプチャされていた
        // C++20以降: 警告/非推奨！[=, this] または [=, *this] と明記する
        auto task = [=, this]() { std::cout << port << "\n"; };
    }
};
```

## 10. 理解度チェッククイズ

### Q1. キャプチャなしラムダ `[](int a, int b) { return a + b; }` について正しい説明はどれですか？
- A. `std::function` にしか代入できない
- B. 通常の C 言語関数ポインタ（`int (*)(int, int)`）に暗黙変換できる
- C. 引数が2つあるためインライン化されない
- D. `mutable` を指定しないとコンパイルエラーになる

<details>
<summary>▶ 解答と解説</summary>

**正解: B**
C++ 仕様により、キャプチャを持たないラムダ式は、対応するシグネチャの関数ポインタ型への暗黙の型変換演算子（conversion operator）を持ちます。
</details>

### Q2. `[ptr = std::move(p)]` のようにムーブキャプチャが必要になる理由は？
<details>
<summary>▶ 解答と解説</summary>

**解答**: `std::unique_ptr` や `std::promise` などの型はコピーコンストラクタが削除された「Move-Only」な型であるため、`[=]` や `[p]` によるコピーキャプチャができません。C++14 の初期化キャプチャを使って `std::move` することで、所有権をラムダ内部に安全に移動できます。
</details>

## まとめ：C++ ラムダ式マスターの三箇条

1. **「キャプチャは最小限に」**: キャプチャなしなら関数ポインタにも化けられる。参照キャプチャ `[&]` は寿命（ライフタイム）に細心の注意を払う。
2. **「受け取りはテンプレート（Concepts）が基本」**: `std::function` はコンテナ保存など必要な時だけ使い、普段は `template <std::invocable>` でゼロオーバーヘッドを保つ。
3. **「IIFE で不変性（`const`）を高める」**: 複雑な初期化ロジックは即時実行ラムダ `[&]{ ... }()` で安全に閉じる。
