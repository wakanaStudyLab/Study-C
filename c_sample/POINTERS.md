## 1. ポインタとは何か？ —「住所」の話

### 📦 変数 = 「箱」、アドレス = 「住所」

プログラムが動くとき、変数はコンピュータの **メモリ（RAM）** という広大な棚のどこかに置かれます。
それぞれの棚には **住所番号（アドレス）** が振られており、
**ポインタとは「その住所を格納する変数」** です。

```
メモリのイメージ（番地と内容）:

  アドレス  │ 内容
  ──────────┼──────
  0x1000    │  42    ← int x = 42; はここに置かれている
  0x1004    │  99    ← int y = 99; はここに置かれている
  0x1008    │ 0x1000 ← int* px = &x; はここに置かれ、x の住所を記憶している
```

> 「ポインタ = その変数がメモリのどこにあるかを示す住所票」

## 2. 宣言と基本操作（& と *）

### 重要な演算子 2 つ

| 演算子 | 読み方 | 意味 |
|--------|--------|------|
| `&x`   | アドレス演算子 | 変数 `x` の住所（アドレス）を取得する |
| `*p`   | 間接参照演算子（デリファレンス） | ポインタ `p` が指す先の中身を読み書きする |

### コード例

```c
int x = 42;       // int 型の変数 x を宣言（値は 42）

int* px = &x;     // px は「int を指すポインタ」。&x で x の住所を取得して格納する
//  ↑
// 「int* 型の変数」= 「int が置かれている住所を入れる変数」

printf("%d\n",  x);    // → 42        （x の値）
printf("%p\n", px);    // → 0x1000    （x の住所、16進数）
printf("%d\n", *px);   // → 42        （px が指す先の中身 = x の値）

*px = 100;             // px の指す先（= x）に 100 を書き込む
printf("%d\n",  x);    // → 100       （x が変わっている！）
```

### 図解

```
変数 x:                     ポインタ px:
┌──────────────┐            ┌──────────────┐
│     42       │ ←─────── │   0x1000     │
│  (アドレス   │  「指す」  │  (x の住所)   │
│   0x1000)    │            │              │
└──────────────┘            └──────────────┘
    &x = 0x1000                  px
    *px = 42
```

## 3. ポインタを使う理由 — 「値渡し」の限界

### C言語は「全引数を値渡し（コピー渡し）」する

```c
void try_change(int n) {
    n = 999;  // これは n のコピーを変えるだけ！
}

int main(void) {
    int x = 42;
    try_change(x);
    printf("%d\n", x);  // → 42  （全く変わっていない）
    return 0;
}
```

`try_change(x)` を呼ぶと、`x` の **コピー** が関数に渡されます。
関数の中でいくら変更しても、`main` の `x` には届きません。

### ✅ ポインタを渡せば呼び出し元を変更できる

```c
void really_change(int* p) {
    *p = 999;  // p が指す先（呼び出し元の x）を直接書き換える
}

int main(void) {
    int x = 42;
    really_change(&x);  // x の「住所」を渡す
    printf("%d\n", x);  // → 999  （変わった！）
    return 0;
}
```

**ポイント:** 住所（ポインタ）は値渡しされますが、その住所を使って元の変数に直接アクセスできます。

### 実例 — swap 関数

```c
void swap(int* a, int* b) {
    int temp = *a;  // a が指す先の値を temp に退避
    *a = *b;        // b が指す先の値を a が指す先に書き込む
    *b = temp;      // temp の値を b が指す先に書き込む
}

int main(void) {
    int x = 10, y = 20;
    swap(&x, &y);
    printf("x=%d, y=%d\n", x, y);  // → x=20, y=10
    return 0;
}
```

## 4. ポインタ演算と配列

ポインタは「住所を保持する変数」なので、住所に対して計算ができます。
ただし普通の整数演算とは動きが異なり、**常に「指している型のサイズ」を単位として動く**のが特徴です。

---

### 4-1. 配列名はポインタに「化ける」（Decay）

```c
int arr[4] = { 10, 20, 30, 40 };

// 配列名 arr は &arr[0] と同じアドレスに評価される（先頭要素への住所）
int* p = arr;       // OK: p は arr[0] を指す
int* q = &arr[0];   // 上と全く同じ意味

printf("%p\n", (void*)arr);     // -> 0x1000（例）
printf("%p\n", (void*)&arr[0]); // -> 0x1000（同じ）
printf("%p\n", (void*)p);       // -> 0x1000（同じ）
```

> ただし `sizeof(arr)` は配列全体のサイズ（16 bytes）を返します。
> ポインタに decay した後の `sizeof(p)` は 8 bytes（ポインタ自体のサイズ）です。

---

### 4-2. 加算・減算（`p + n` / `p - n`）

ポインタに整数を足すと、**型のサイズ（バイト数）× n** だけアドレスが移動します。

```
int のサイズ = 4 バイト として:

  メモリ:
  アドレス  | 値
  ----------+----
  0x1000    | 10   <- arr[0]   p + 0 が指す場所
  0x1004    | 20   <- arr[1]   p + 1 が指す場所
  0x1008    | 30   <- arr[2]   p + 2 が指す場所
  0x100C    | 40   <- arr[3]   p + 3 が指す場所
```

```c
int arr[4] = { 10, 20, 30, 40 };
int* p = arr;  // p は arr[0] を指す

printf("%d\n", *(p + 0));  // -> 10  (arr[0])
printf("%d\n", *(p + 1));  // -> 20  (arr[1])
printf("%d\n", *(p + 2));  // -> 30  (arr[2])
printf("%d\n", *(p + 3));  // -> 40  (arr[3])
```

減算も同様です：

```c
int* p = &arr[3];  // arr[3] = 40 を指す
printf("%d\n", *(p - 1));  // -> 30  (arr[2])
printf("%d\n", *(p - 2));  // -> 20  (arr[1])
```

---

### 4-3. インクリメント・デクリメント（`p++` / `p--`）

ポインタを 1 つ進める・戻す操作です。配列を「順番になめる」ループで頻繁に使います。

```c
int arr[4] = { 10, 20, 30, 40 };
int* p = arr;  // arr[0] を指す

printf("%d\n", *p);  // -> 10  (arr[0])
p++;                 // p が arr[1] を指すよう 4 バイト進む
printf("%d\n", *p);  // -> 20  (arr[1])
p++;
printf("%d\n", *p);  // -> 30  (arr[2])
```

```c
// ポインタのインクリメントで配列を走査する（よく使うパターン）
int arr[4] = { 10, 20, 30, 40 };
for (int* p = arr; p < arr + 4; p++) {
    printf("%d ", *p);
}
// -> 10 20 30 40
```

#### ⚠️ `*p++` と `(*p)++` の違いに注意

演算子の優先順位の関係で、意味が全く異なります：

```c
int arr[3] = { 10, 20, 30 };
int* p = arr;

// --- *p++ ---
// 後置 ++ は * より後に評価される
// 意味: 「*p の値（10）を読んでから、p を次の要素へ進める」
int val = *p++;
printf("val=%d\n", val);  // -> 10  (arr[0] の値)
printf("*p=%d\n",  *p);   // -> 20  (p は arr[1] に移動済み)
```

```c
// --- (*p)++ ---
// 意味: 「p が指す先の値（arr[0]）を 1 増やす」
// ポインタ p 自体は動かない
int arr[3] = { 10, 20, 30 };
int* p = arr;
(*p)++;
printf("arr[0]=%d\n", arr[0]);  // -> 11  (arr[0] が変わった)
printf("*p=%d\n",     *p);      // -> 11  (p は arr[0] を指したまま)
```

一覧でまとめると：

| 書き方 | p は動く？ | 指す先の値は変わる？ | 操作の意味 |
|--------|-----------|-------------------|-----------|
| `p++`    | ✅ 次へ進む   | ❌ 変わらない | ポインタを次の要素へ |
| `p--`    | ✅ 前へ戻る   | ❌ 変わらない | ポインタを前の要素へ |
| `++p`    | ✅ 次へ進む   | ❌ 変わらない | 先に進んでから値を使う |
| `*p++`   | ✅ 次へ進む   | ❌ 変わらない | 現在の値を読んでから次へ進む |
| `(*p)++` | ❌ 動かない   | ✅ +1 される  | 指す先の値を 1 増やす |
| `*++p`   | ✅ 先に進む   | ❌ 変わらない | 先に次へ進んでからその値を読む |

---

### 4-4. ポインタ同士の引き算（`p2 - p1`）

**同じ配列内の** 2 つのポインタを引くと、「要素数の差」が得られます（バイト数ではなく要素数）。

```c
int arr[5] = { 10, 20, 30, 40, 50 };
int* p1 = &arr[1];  // arr[1] を指す
int* p2 = &arr[4];  // arr[4] を指す

// ptrdiff_t: ポインタ差分専用の符号付き整数型 (<stddef.h> または <stdio.h> で定義)
ptrdiff_t diff = p2 - p1;
printf("%td\n", diff);  // -> 3  (インデックス 4 - 1 = 3 要素分の差)

// 実際のアドレス差は 3 * sizeof(int) = 12 バイトだが、
// ポインタの引き算は自動的に「要素数」に換算してくれる
```

> ⚠️ 異なる配列のポインタ同士を引き算するのは**未定義動作**です。

---

### 4-5. ポインタの比較（`<` / `>` / `==` / `!=`）

同じ配列内のポインタ同士はアドレスの大小で比較できます。
配列を「前から後ろへ」なめる終了条件としてよく使われます。

```c
int arr[4] = { 10, 20, 30, 40 };
int* start = arr;      // 先頭を指す
int* end   = arr + 4;  // 末尾の「次」を指す（番兵ポインタ: 有効な要素を指さない）

// start < end の間、順番に処理する
for (int* p = start; p < end; p++) {
    printf("%d ", *p);
}
// -> 10 20 30 40
```

同じアドレスかどうかの確認：

```c
int* p = arr;
p += 4;               // arr の末尾の次に移動
if (p == arr + 4) {   // 同じアドレスなら true
    printf("先頭から 4 つ進んだ\n");
}
```

---

### 4-6. `arr[i]` と `*(p + i)` は完全に同じ

C言語の規格上、`a[i]` は `*(a + i)` と**完全に等価**です。

```c
arr[2]      // 配列の書き方（シンタックスシュガー）
*(arr + 2)  // ポインタ演算の書き方（コンパイラ内部でこちらに変換される）
// どちらも同じメモリの中身 (30) を読む
```

```c
// 2通りの書き方で配列を全部表示する
for (int i = 0; i < 4; i++) {
    printf("arr[%d] = %d,  *(p+%d) = %d\n",
           i, arr[i], i, *(p + i));
}
// arr[0] = 10,  *(p+0) = 10
// arr[1] = 20,  *(p+1) = 20
// arr[2] = 30,  *(p+2) = 30
// arr[3] = 40,  *(p+3) = 40
```

### 4-7. ⚠️ 境界外アクセス（Out-of-Bounds）— 最も危険なバグ

ポインタ演算で配列の範囲外を指してしまうと、**未定義動作 (Undefined Behavior)** になります。
C言語はインデックスの範囲チェックを一切しません（Rust と決定的に異なる点）。

```c
int arr[4] = { 10, 20, 30, 40 };
int* p = arr;

// ❌ 範囲外アクセス: arr は 0~3 番目までしか存在しない
printf("%d\n", *(p + 4));  // arr[4] は存在しない -> 隣のメモリを読む（UB）
printf("%d\n", *(p - 1));  // arr[-1] は存在しない -> 手前のメモリを読む（UB）

p += 10;  // はるか遠くを指す
*p = 0;   // ❌ 完全に別の領域を破壊する可能性（クラッシュ or サイレントバグ）
```

> 🔥 境界外アクセスはクラッシュしないこともあります。
> クラッシュしない場合の方が厄介で、気づかないままデータが壊れたり、
> セキュリティ脆弱性（バッファオーバーフロー攻撃）につながります。

**対策:**
- ループの終了条件に `p < arr + N` のような番兵ポインタを使う
- インデックスアクセスの前に `i < N` を必ず確認する
- `valgrind` や AddressSanitizer（`-fsanitize=address`）などのツールで検出する

## 5. ヒープメモリ — malloc と free

### スタックとヒープの違い

| 種類 | 確保タイミング | 解放タイミング | 用途 |
|------|--------------|--------------|------|
| **スタック** | 変数宣言時に自動 | スコープを抜けると自動 | ローカル変数 |
| **ヒープ** | `malloc()` を呼んだとき | `free()` を呼んだとき（**手動**） | 実行時に決まるサイズ、関数をまたぐデータ |

### malloc / free の基本

```c
#include <stdlib.h>

// ① 確保: int 5個分のメモリをヒープから確保する
int* arr = (int*)malloc(5 * sizeof(int));
//                       ↑          ↑
//                    個数      1要素のバイト数（sizeof で安全に書く）

// ② NULL チェック（必須！）: メモリ不足のとき malloc は NULL を返す
if (arr == NULL) {
    printf("メモリ確保失敗！\n");
    return 1;
}

// ③ 使う
for (int i = 0; i < 5; i++) {
    arr[i] = (i + 1) * 10;  // 10, 20, 30, 40, 50
}

// ④ 解放（必須！）: 使い終わったら必ず free する
free(arr);
arr = NULL;  // ← おまじないではなく重要（後述）
```

### sizeof を使う理由

```c
// ❌ 危険: 環境によって int のサイズが違うため
int* p = malloc(5 * 4);

// ✅ 安全: 実際の型サイズをコンパイラが計算してくれる
int* p = malloc(5 * sizeof(int));
```

## 6. ポインタの3大バグ

C言語でポインタを使うとき、必ず気をつけるべき 3 つのバグがあります。
Rust はこれらをコンパイル時に防いでいます。

---

### ❌ バグ① メモリリーク (Memory Leak)

`free` を忘れると、そのメモリはプロセスが終了するまで解放されません。
長時間動くプログラムでは少しずつメモリが食い尽くされます。

```c
void leak_example(void) {
    int* p = (int*)malloc(100 * sizeof(int));
    // ... 使う処理 ...
    return;  // ❌ free を忘れた！ 100 * 4 = 400 バイトが永遠に占有される
}
```

**✅ 対策:** 全ての `malloc` に対応する `free` を必ず書く。

---

### ❌ バグ② Use-After-Free（解放済みメモリへのアクセス）

`free` した後のメモリを読み書きすると、**未定義動作 (Undefined Behavior)** になります。
クラッシュすることもあれば、気づかず壊れたデータを使い続けることもあります。

```c
int* p = (int*)malloc(sizeof(int));
*p = 42;
free(p);     // メモリを解放

*p = 99;     // ❌ 解放済みのメモリに書き込み！（何が起きるか分からない）
printf("%d\n", *p);  // ❌ 解放済みのメモリを読み込み！
```

**✅ 対策:** `free` の直後に `p = NULL;` を代入する。
`NULL` へのアクセスは必ずクラッシュ（Segmentation Fault）するため、バグを早期発見できます。

```c
free(p);
p = NULL;    // ← これで *p のアクセスは即クラッシュ → バグが分かりやすくなる
```

---

### ❌ バグ③ 二重解放 (Double Free)

同じポインタを 2 回 `free` すると、**ヒープ管理構造が壊れて** クラッシュや脆弱性につながります。

```c
int* p = (int*)malloc(sizeof(int));
free(p);   // 1回目: OK
free(p);   // ❌ 2回目: ヒープ破壊！（プログラムがクラッシュまたは悪意ある挙動）
```

**✅ 対策:** `free` 後に `p = NULL;` を代入する。
`free(NULL)` は安全なノーオペレーション（何もしない）なので、誤って 2 回 `free` しても安全になります。

```c
free(p);
p = NULL;  // これで free(p) を再度呼んでも何も起きない（free(NULL) は安全）
```

## 7. 多重ポインタ（int**）

### 「ポインタのポインタ」が必要になる場面

関数の中でヒープ確保し、その **ポインタ変数そのもの** を呼び出し元に書き戻したいとき、
`int**`（ポインタのポインタ）が必要になります。

### なぜ int* だけでは足りないのか

```c
// ❌ これは動かない（int* はコピーで渡されるため）
void allocate(int* p, size_t n) {
    p = malloc(n * sizeof(int));  // ローカルのコピー p を変えるだけ
    // 呼び出し元のポインタ変数は変わらない！
}

int main(void) {
    int* arr = NULL;
    allocate(arr, 5);
    // arr はまだ NULL のまま
    return 0;
}
```

### ✅ int** を使えば解決

```c
// ✅ out_ptr は「int* 型の変数のアドレス（住所）」
void allocate(int** out_ptr, size_t n) {
    *out_ptr = (int*)malloc(n * sizeof(int));
//   ↑
// *out_ptr は「out_ptr が指す先」= 呼び出し元の int* 変数 そのもの
}

int main(void) {
    int* arr = NULL;
    allocate(&arr, 5);  // arr の住所（int**）を渡す
    // arr は確保したメモリを指している！
    free(arr);
    return 0;
}
```

### 図解

```
main 内の arr:              allocate 内の out_ptr:
┌──────────────┐            ┌──────────────┐
│    NULL      │ ←─────── │  &arr のアドレス │
│  (arr の住所は │  「指す」  │              │
│   0x2000)   │            └──────────────┘
└──────────────┘
      ↑
  *out_ptr = malloc(...)  でここを書き換えられる
```

## 8. NULL ポインタ

`NULL` は「どこも指していない」を表す特別な値（通常は `0`）です。

```c
int* p = NULL;  // 「まだ何も指していない」という明示的な初期化

if (p == NULL) {
    printf("ポインタは無効です\n");
}

*p = 42;  // ❌ NULL を参照外しすると即クラッシュ (Segmentation Fault)
          // ← これはバグだが、少なくとも「すぐ気づける」点は良い
```

**ルール:**
- ポインタ変数は宣言時に必ず `= NULL` で初期化する
- `free` した後は必ず `= NULL` を代入する
- ポインタを使う前に `!= NULL` をチェックする

## 9. よくある混乱ポイントまとめ

### 🤔 `int* p` と `int *p` どちらが正しい？

どちらも同じです。C言語では慣例的に `int *p` と書く人が多いですが、
「ポインタ型」として強調したい場合は `int* p` と書く人もいます。

```c
int* p;   // OK（型強調スタイル）
int *p;   // OK（C伝統スタイル）
int * p;  // OK（スペースあり）
// ただし int* a, b; は「int* a と int b」なので注意！
// int* a, *b; と書くか、1行1変数にすべき
```

---

### 🤔 `*p` の意味が宣言と使用で違う？

```c
int* p;   // 宣言: 「p はポインタ型だ」という意味（* は型の一部）
*p = 42;  // 使用: 「p が指す先に 42 を書き込む」という意味（* は演算子）
```

宣言の `*` と、式の中の `*` は役割が全く異なります。

---

### 🤔 配列とポインタは同じもの？

**似ているが異なります。**

```c
int arr[4] = { 1, 2, 3, 4 };
int* p = arr;  // arr は p に代入できる（Decay）

// 違い:
sizeof(arr)  // → 16 バイト（配列全体のサイズ）
sizeof(p)    // → 8 バイト（ポインタ自体のサイズ、64bit 環境）

arr = p;  // ❌ コンパイルエラー: 配列変数自体は再代入できない
p   = arr;  // ✅ OK
```

---

### 🤔 `p++` vs `(*p)++` の違い

```c
int arr[3] = { 10, 20, 30 };
int* p = arr;

p++;    // p 自体を進める（次の要素を指すようにする） → p は arr[1] を指す
(*p)++; // p が指す先の値を +1 する → arr[0] が 11 になる
```

## 🔑 まとめ

| 概念 | キーワード | 一言説明 |
|------|-----------|---------| 
| ポインタ | `int* p` | 変数の住所を格納する変数 |
| アドレス取得 | `&x` | 変数 x の住所を得る |
| 参照外し | `*p` | ポインタの指す先の値を読み書きする |
| ポインタ加算 | `p + n` | 型のサイズ × n バイト先を指す |
| インクリメント | `p++` | 次の要素を指すよう 1 つ進む |
| 値のインクリメント | `(*p)++` | 指す先の値を 1 増やす（p は動かない） |
| ポインタ差分 | `p2 - p1` | 同一配列内の要素数の差を得る |
| ポインタ比較 | `p < end` | 配列走査の終了条件に使う |
| ヒープ確保 | `malloc()` | 実行時に動的にメモリを確保する |
| ヒープ解放 | `free()` | 確保したメモリを必ず返却する |
| NULL 代入 | `p = NULL` | free 後の安全対策 |
| ダブルポインタ | `int** pp` | 関数からポインタを書き戻す |

> **一番大切なこと:** `malloc` したら必ず `free`、`free` したら必ず `NULL` 代入。
